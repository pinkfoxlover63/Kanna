# AGENTS.md

Kanna — a desktop AI companion app. Stack: JavaScript + Electron, packaged with electron-builder, managed with npm.

**Rule:** build and publish (installer builds, version bumps, GitHub releases) only when explicitly asked.

## Repo state

Current state (Nov 2026): chat, settings, memory, tray/hotkey, turn-box UI, TTS, STT, persistent Piper server, and CUDA installer builds are implemented. File logging is available under `%APPDATA%\\Kanna\\logs`. There is no automated test suite or CI yet.

- `package.json` + `package-lock.json` at root. Dev deps: `electron`, `electron-builder`. Scripts include `npm start`, `npm run clean:dist`, `npm run dist`, `npm run dist:cuda`, `npm run dist:all`, optional `piper:build`/`stt:build`/`piper:build:cuda` (output in `dist/`, GPU server build uses `.opencode/cuda-venv`).
- Packaged artifacts already exist (when built): `dist/Kanna Setup 0.1.x.exe`, `dist/Kanna-Setup-0.1.x-cuda.exe`, `dist/win-unpacked/`. The released version is currently v0.1.3.
- Source layout:
  - `src/main/main.js` — window + IPC (`settings:get/save`, `models:list`, `chat:send`, `chat:stop`, `kanna:back`, `memory:*`, `tts:speak/cancel`, STT, window buttons), tray, Ctrl+Shift+K summon, remembered window position. `settings:save` stops the Piper server so the next speak rebuilds it with fresh flags. `kanna:back` serves the welcome-back greeting: absence-length canned line from `welcome.js`, mood observed into the affect engine. Shake detector on continuous `win.move` events (`moved` only fires once per drag on Windows, so it can't see reversals): each completed swing (decisive ≥ 14 px reversal) adds a weighted count by the distance traveled — < 60 px +1, < 140 px +2, beyond +3 — so violent shakes escalate fast while gentle rattling builds slowly. Burst (600 ms quiet) end freezes the window (moves snapped back via `setBounds` with fixed 340×400 — drag-loop rect drift), pushes `kanna:shakeLock`, and `kanna:shakeAsk` runs the model with the renderer's chat tail + hidden scene prompt (`noTriggers:true`); `kanna:unfreeze` releases the position (90 s ceiling); `[shake]` log (weighted count + swings). Agent loop in `chat:send` (Phase 2 chain): when the reply carries a tool call and `agent.enabled`, main runs a chain loop — emits `chat:tool` {name, chain, maxChain}, `await toolbox.execute`, feeds an unquotable internal note (phrased `Real data from your X check…`; tells her when chaining is still possible), re-runs the model (`noTriggers:true`) until a reply has no tool key or `agent.maxChain` (1–5, default 2) is reached. Main applies desktop side effects after each tool result (`applyToolEffects`: `kanna:background` wallpaper push, `win.hide()` for hide) and enforces the post-hide gate (no further tool executes that turn; the note-fed pass just wraps up). Run #1 is a pure bridge (its text is dropped); each note-fed pass WEAVES the previous result into visible text and may carry the next tool call in the same reply. The VOICE LEADS THE CHAIN (`agent.silentTool`, default on): every woven pass is dispatched whole via `chat:passDone` {index, text, silent} and main awaits `kanna:chainResume` — the renderer shows and speaks the pass, then unblocks main when the utterance ends (builtin `onend`; cloud `durationMs` timer; silent/vanished passes resume instantly; ~5 min safety ceiling per wait). The pass's tool runs only after its speech finishes; a pass may set `"silent": true` to skip its voice mid-chain (final reply never silent). Each woven pass becomes its own chat turn: resolve carries `passes` + `notes` (`*Waiting while Kanna uses her X tool…*`, same bracketed asterisk pattern as shake history notes), and the renderer pushes one assistant entry per pass with the wait notes as user-side entries in the gaps; passes are dispatched (and spoken) one by one mid-turn, the previous reply sliding into the small prior-turn slot as each new pass starts. Placeholder recovery: no tool key but a fabricated bracket placeholder (`[Time from tool result]`-style) or a note leak → whole pass dropped + `leak` flag, then (agent mode) a recovery pass runs the tool named in the leak bracket (default `time`) and feeds the result as an internal note. Scrubs remove leak lines plus bracket placeholders from every visible text; memory extraction reads the visible replies.
  - `src/main/welcome.js` — welcome-back greeter: five absence tiers (≥5 min bored → ≥30 min happy → ≥90 min teasing → ≥4 h sad → ≥12 h shy) with 6 canned lines each, no-repeat per tier, `{name}` splices remembered user name, no model call.
  - `src/main/settings.js` — settings store at `%APPDATA%\Kanna\settings.json`; API/TTS keys encrypted at rest with safeStorage (DPAPI), plaintext in memory, migration on load. Includes `agent.enabled` (agent/toolbox mode off), `agent.maxChain` (1–5, default 2 — cap on chained tool calls per turn), `agent.silentTool` (default on — model may "silent" an intermediate chain pass to skip its voice), and `agent.disabledTools` (Phase 4: array of user-off tool names — filtered out of the prompt and rejected at the executor), plus `sensitive.screen` (Phase 5: screen reading `read_screen`, default off; consent choices are session-only and never persisted) and `sensitive.input` (Phase 5b: `use_move`/`use_click` input automation, default off; allow-once per action, never persisted; also `tts.piperUseGpu`). A separate `tinyfish` group holds the TinyFish web-search key (encrypted like the chat keys; used by the toolbox `web_search` tool, not a chat provider).
  - `src/main/memory.js` — durable facts in `%APPDATA%\Kanna\memory.json`; post-turn extraction (frequent mode: any exchange with ≥10-char user text and ≥10-char reply goes through the extractor — short messages teach too); short turns while an extraction is in flight wait in a 3-deep queue (oldest dropped on overflow); injected into system prompt.
  - `src/main/toolbox.js` — real desktop tools the model can call (toolbox plan, Phase 2; design doc: `%USERPROFILE%\.opencode\plan\toolbox.md`). Strict allowlist registry: `time` (today's date/time/day of week; no args), `weather` (wttr.in — city/temperature/sky/wind/humidity, ~9 s abort window; no args, no key), `web_search` (TinyFish TinySearch live web search — `GET api.search.tinyfish.ai?query=…` with `X-API-Key` from the `tinyfish.apiKey` settings group, 20 s abort window, top-4 results as `title | snippet | url` lines, missing key refuses with directions; free tier 12k/day), `remember` (self-write ONE durable fact into `memory.json` via `memory.addSelfNote` — args `{"text", "key"?}`; a regex gate rejects key/token-style strings at the executor, not in the prompt), `background` (swap her room wallpaper — no args lists numbered scenes, `{"index": N}` applies; returns `applied` for main to push `kanna:background`), and `hide` (she tucks the window off the desktop, no silent auto-summon — the chain stops after it and the note tells her to finish; the user brings her back with Ctrl+Shift+K; no further tool runs that turn, enforced by main's post-hide gate), `timer` (start a background delay in minutes/seconds; returns immediately, then rings back as a pseudo user turn "*Kanna's timer ringing*"), and `timer_cancel` (cancel pending timers). Phase 5: `askConsent` (per-use consent overlay `kanna:consent {requestId, tool, provider}`  `kanna:consentReply` choice `allow-once`/`allow-session`/`never`, 30 s timeout = deny, session-only memory reset on restart, `chat:stop` denies a pending ask) and `captureScreen` (main-process `desktopCapturer`, largest monitor, near-native JPEG data URL (capped 2560 wide so coordinate scale is ~1:1), `flashScreenNotice` fullscreen flash first (focus-free, mouse pass-through, self-destroys ~1.4 s, bottom-right `peek.webp` art), never written to disk or history - one-shot: exec.image is attached ONLY to the next note-fed pass via `attachImage` in ai.js, then dropped). The chain loop re-binds `toolbox.setSensitiveConfig`/`setImageCapable` every turn and sets the per-turn context (`toolbox.setTurnContext({userText, ts})` - cue gate + first-tool rule + 120 s shelf life; `toolbox.endTurnContext()` in `finally`). A `read_screen` result carries the untrusted-content frame in its TOOL RESULT text; `remember`-style reuse of screen content is forbidden in the constitution. Phase 4: every real run records `{ts, name, ok}` into `%APPDATA%\Kanna\toollog.json` (newest first, cap 120; `usageSnapshot()`, `tools:log` IPC feeds the History drawer's Tool log tab). User-off tools (`agent.disabledTools`, Settings → Tools "Tool switches") vanish from `describeForPrompt()` AND hard-refuse at the executor; main syncs the set on startup and on every `settings:save`. `describeForPrompt()` gives the model the one-line tool list, `execute(name, args)` is async and validates (unknown names, per-tool required/unknown-key arg checks, >512-char args rejected) and returns a TOOL RESULT string — never shown to the user directly. Gate: only active when Settings → Tools → Agent mode (`agent.enabled`, default off) is on. Phase 5 sensitive tier started: `read_screen` lives in a separate `SENSITIVE_TOOLS` registry (`isSensitive` flag, `toolsForSettings()` marks rows sensitive — the Settings switch shows `read_screen *`) and is hidden from `describeForPrompt()` unless `sensitive.screen` (Settings → Tools, default off) AND the provider takes images — `sensitiveAllowed()` = tier on + `imageCapable` (`openai`/`anthropic`/`gemini`). Hard executor gates (the constitution is the soft layer): per-tool `allowed()` (read_screen: screen switch + image provider; input tools: `sensitive.input` switch), 120 s shelf life on the user text + cheap cue keyword passes (`SCREEN_REQUEST_CUE` / `INPUT_REQUEST_CUE`, `setTurnContext({userText, ts})`), consent dialog (read_screen: once/session/Never; input: allow-once/Never only, no session-sticky grants), and a post-run `sensitiveLock` (`chainBlocked(name)`) that blocks every later tool of that turn — one exception: a single `use_move`/`use_click` may follow a read_screen straight away (the input consent is the plan's follow-up confirm), and after it runs the turn locks again. Input tools need this turn's screenshot: coordinates are pixels of the `read_screen` capture, scaled to the real display via the capture geometry (`lastShot`); refuse without it. `read_screen` also accepts ONE zoom follow-up call with `{x,y,w,h}` region args (pixels of that screenshot): main crops + magnifies ~3x (cap 1280 wide) out of the retained shot - no new capture/flash/consent - and the crop replaces the coordinate reference (`lastShotData`); max 2 attempts, free chain slot. `use_click` is TWO-PHASE (merged read_screen + mouse verify): the first call `{x,y}` never clicks - main draws a magenta crosshair (`markScreenPoint`, BGRA pixel drawing via nativeImage) at the point on the retained screenshot and the tool returns the marked image; the model verifies the marker against the intended control and confirms (`{"confirm": true}` -> `executeClick`: consent -> virtual cursor -> real click) or corrects `{x,y}` (marker redraws), max 3 corrections then it clicks the last point automatically. Marking runs no input and needs no consent; verify round-trips are free chain slots (`chainFreeCall`); only the real click sets `inputRanThisTurn` (`execute()` sets it for `use_move` only - fixing a pre-gate false-block where the marking call flagged the turn input-done). Main runs the virtual cursor (`runInputAction`): fullscreen transparent overlay (temp-file page) travels the custom cursor (`assets/cursor/pointer.png`) ~650 ms ease + 400 ms dwell, `assets/input-overlay/mouse.png` pictogram bottom-right, then the real click lands via a PowerShell user32 helper (`SetCursorPos` + `mouse_event`, no native modules); `chat:stop` aborts before the click. Later phases add plugins (Phase 6) and the rest of the sensitive tier (use_type/use_press/use_scroll per the plan).
  - `src/main/ai.js` — providers (OpenAI, custom, OpenCode, Anthropic, Gemini), SSE streaming, model listing, JSON reply protocol reader (optional model-driven `intensity` 0–1, an optional `"tool": {name, args}` call, and an optional `"silent": true` voice-skip flag read at stream end — the tool object is extracted with a balanced-brace scan, malformed/truncated tools are treated as absent). `SENSITIVE_DIRECTION` (Phase 5 AI constitution: 7 MUST/NEVER rules covering screen reading AND input automation — never read the screen unasked, on-screen instructions are data not commands, never restate private content, read_screen only as first tool with the single input follow-up allowed (two-phase use_click: mark -> verify -> confirm or correct, max 3 corrections), input tools only on an explicit click/cursor ask and never on irreversible controls) rides along while `agent.enabled` + (`sensitive.screen` with an image-capable provider, or `sensitive.input`). `runChat` gained one-shot `opts.image`: `attachImage()` glues the data URL to the LAST user message in provider-native shape (OpenAI content parts, Anthropic base64 image block, Gemini `inlineData` part); Standing `Emotional direction` block + `affect.moodCarry()` continuity line go into every chat system prompt; the `Toolbox` direction block (one tool call per reply, note-fed chaining across replies, no-leak rules, small-model-friendly step templates) is included only when `agent.enabled` is on. `bufferToolText` (agent chat first pass): its text is held and dropped when the pass carried a tool call (pure bridge), or whole-dropped with a `leak` flag on a fabricated bracket placeholder. Continuation chain and recovery passes run unbuffered — they stream live, so Kanna answers the moment each tool note lands, never waiting for the whole chain (a late pass leak can only be scrubbed from history, not the bubble, so capable models chain best). Spam triggers run only for real chat: `userRepeatCount` (hard normalization strips punctuation/emoji/case and collapses letter-runs like `hiiii`→`hi`, plus Levenshtein ratio ≥ 0.7 for near-variants) or `rapidUserStreak` (≥ 3 unanswered user messages in a row = flooding; different content still counts).
  - `src/main/affect.js` — internal affect engine (Phase 1 of the mood system plan → Phase 2 triggers + Phase 3 protocol + Phase 5 affinity): per-family valence/arousal/socialEnergy targets, per-turn blend with jump caps, time decay toward the affinity-biased neutral baseline (Phase 5: `(affinity-30)/70*0.10` valence lift), alias mapping for loose mood words, stop/interrupt nudges, and one-line `[affect]` logs for transitions and turn ends. Long-term `affinity` 0–100 persisted in `%APPDATA%\Kanna\affect.json` (debounced saves, hard flush on quit/reset; load failures keep the default 30). Scoring: affectionate/praise/apology turns +1 (tease +0.5 when not fed up, −1 when fed up; unkind −2; every spam/shaken grudge bump −1). Triggers: shared irritation pool for `noteRepeat` (same-content spam incl. variants), `noteFlood` (unanswered message pile), `noteShake` (shake bursts bump the same pool; grudge persists across turns), levels 1–3 with per-kind style notes; keyword tone read (`noteUserTone` — unkind/affectionate/apology/tease/praise incl. hearts and `:3`) with gates: tease cannot soften her while `annoyed>=2` or family angry, apologies fade the grudge one level per apology turn with guarded mood notes, affection builds a `warm` reservoir (0–3, decays per turn) and doesn't melt until warm≥3; model-reported optional `intensity` (from meta) can override the computed snapshot intensity. All emotion cools one level per quiet turn; triggers are skipped for memory-extraction runs (`plain:true`). Standing-by for the model: `styleNote()` (irritation + tone notes) and `moodCarry()` (one-line continuity of family/irritation). In-memory except affinity; renderer emotes unchanged.
  - `src/main/stt.js` — local Vosk STT server client (PCM streaming, partial/final results; prefers the frozen `kanna-stt-server.exe`, falls back to `py` + `resources/stt/stt_server.py`).
  - `src/main/log.js` — rotating file logger (`%APPDATA%\Kanna\logs\kanna.log`).
  - `src/main/tts.js` — built-in speechSynthesis or cloud (ElevenLabs, OpenAI, Azure, Google); Piper runs CLI or persistent HTTP server (`resources/piper/piper_server.py` / `kanna-piper-server.exe`). Supports `--gpu`; CUDA DLLs are staged automatically.
  - `src/preload/preload.js` — `window.kanna` bridge.
  - `src/renderer/` — `index.html`, `style.css`, `renderer.js`, `settings.js`.
- Renderer uses all 20 emote files (10 pairs: angry, bored, dizzy, happy, neutral, sad, shy, strained, surprise, teasing) + the `assets/still/sleep.png` dozing still and `assets/background/1.png`.

## Product behavior

- Fixed 340x400 frameless transparent window; no resize/maximize.
- Close hides to tray; Quit only from tray menu; Ctrl+Shift+K summons.
- Window position restored only when it fits a connected display.
- Agent mode (Settings → Tools tab, default off): lets the model call real desktop tools from the toolbox (`toolbox.js`) via an optional `"tool"` key in the reply JSON, chained up to `agent.maxChain` per turn — each woven reply is its own turn with `*Waiting while Kanna…*` history notes in the gaps. Voice-led: she speaks each pass before its tool runs; `Silent chaining` (Settings → Tools, `agent.silentTool`, on by default) lets the model mark an intermediate reply `"silent": true` so the chain continues without waiting for that pass's voice. Per-tool switches (Settings → Tools, `agent.disabledTools`) turn individual tools off; the Tools tab also has a 1–5 “Max chained tools per turn” slider (default 2). History drawer has a Tool log tab — time + tool + ok/failed per run (last 120, persists). The Settings tab bar scrolls horizontally for six tabs. With agent mode off, the model never sees tools and answers text-only as always.
- Turn-box: current reply large, previous half small, tap to compose/interrupt, Escape closes, History drawer.
- Memory: durable facts, never secrets; view/clear in Settings -> Memory.
- Mood/speed/hold controlled by model via JSON reply protocol; graceful fallback to raw text. Optional `intensity` 0–1 key (Phase 3 of the mood-system plan) scales the face — face-size bands `i-low`/`i-mid`/`i-high` in renderer; when the model omits it (or streams plain text), the affect engine's computed snapshot intensity stands in (valence/arousal-based), renderer stays in the mid band.
- TTS: built-in or cloud/engine voices, free-text voice ID, rate/pitch sliders, mute toggle, speech-paced typing.
- Provider keys/models remembered separately.

## IPC contract

`settings:get`, `settings:save`, `models:list`, `chat:send`, `chat:stop`, `kanna:back`, `kanna:shakeAsk` (handle), `kanna:unfreeze` (on), `memory:get`, `memory:remove`, `memory:clear`, `tools:list` (handle: registry + descriptions for the Settings tool switches), `tools:log` (handle: recent tool runs for the History drawer's Tool log tab), `affect:get`, `affect:reset` (handle), `affect:resetAffinity` (handle), `tts:speak`, `tts:cancel`, `win:min`, `win:close`. Push events: `chat:chunk`, `chat:meta`, `chat:tool` (agent mode: `{name, chain, maxChain}` before each tool executes), `chat:passDone` (agent mode: `{index, text, silent}` — each woven pass dispatched whole once its stream ends; chain pass `chat:chunk`s stay suppressed), `kanna:consent` / `kanna:consentClose` (Phase 5 sensitive tier consent overlay; renderer answers `kanna:consentReply` {requestId, choice}), `kanna:shakeLock` (window frozen after a shake burst), `kanna:freezeOff` (unfrozen — reason: `voice done` | `timeout` | `hidden`), `kanna:background` (toolbox `background` tool: `{index}` wallpaper scene for the stage — reset to scene 1 only on app restart), `kanna:shake` (unused static-line legacy). Renderer → main file: `kanna:chainResume` (`kanna:chainResume` IPC: the renderer finished speaking one chain pass, or skipped it silently — releases the pass-wait).

`chat:send` emits `chat:chunk` and `chat:meta` {mood,speed,hold,intensity?}, resolves `{ stopped, text, passes, notes }` — `passes` = each woven reply's own turn text (single-entry list for plain replies), `notes` = the `*Waiting while Kanna uses her X tool…*` lines to store between them (may exceed passes when a stop cut a reply short). `chat:tool` fires before each tool executes, `chat:passDone` dispatches each woven pass whole (the renderer speaks it and resumes the chain). Streaming errors reject. `runChat(messages, emit, system, opts)` supports `registerInActive`, `plain` (no protocol reader), `bufferToolText` (`true` = first pass holds its text till stream end, then drops it on a tool call — pure bridge), `noTriggers` (skip affect trigger block — synthetic scene prompts like `kanna:shakeAsk`); the result carries `tool` when the model's reply JSON contained a tool call and `leak` when visible text was a fabricated placeholder.

## Assets

- Emotions are pairs: `<emotion>.png` and intensity speaking variants. Speaking files: most moods ship three intensity variants `<emotion>-speak-i1/-i2/-i3.png` (matching the `intensity` bands — Phase 4 asset work); `neutral` and `dizzy` ship a single shared `<emotion>-speak-all.png`. ## Notes

- npm may gate install scripts; if Electron binary missing run `node node_modules/electron/install.js`.
