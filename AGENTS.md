# AGENTS.md

Kanna — a desktop AI companion app. Stack: JavaScript + Electron, packaged with electron-builder, managed with npm.

**Rule:** build and publish (installer builds, version bumps, GitHub releases) only when explicitly asked.

## Repo state

Current state (Nov 2026): chat, settings, memory, tray/hotkey, turn-box UI, TTS, STT, persistent Piper server, and CUDA installer builds are implemented. File logging is available under `%APPDATA%\\Kanna\\logs`. There is no automated test suite or CI yet.

- `package.json` + `package-lock.json` at root. Dev deps: `electron`, `electron-builder`. Scripts include `npm start`, `npm run clean:dist`, `npm run dist`, `npm run dist:cuda`, `npm run dist:all`, optional `piper:build`/`stt:build`/`piper:build:cuda` (output in `dist/`, GPU server build uses `.opencode/cuda-venv`).
- Packaged artifacts already exist (when built): `dist/Kanna Setup 0.1.x.exe`, `dist/Kanna-Setup-0.1.x-cuda.exe`, `dist/win-unpacked/`. The released version is currently v0.1.3.
- Source layout:
  - `src/main/main.js` — window + IPC (`settings:get/save`, `models:list`, `chat:send`, `chat:stop`, `kanna:back`, `memory:*`, `tts:speak/cancel`, STT, window buttons), tray, Ctrl+Shift+K summon, remembered window position. `settings:save` stops the Piper server so the next speak rebuilds it with fresh flags. `kanna:back` serves the welcome-back greeting: absence-length canned line from `welcome.js`, mood observed into the affect engine. Shake detector on continuous `win.move` events (`moved` only fires once per drag on Windows, so it can't see reversals): each completed swing (decisive ≥ 14 px reversal) adds a weighted count by the distance traveled — < 60 px +1, < 140 px +2, beyond +3 — so violent shakes escalate fast while gentle rattling builds slowly. Burst (600 ms quiet) end freezes the window (moves snapped back via `setBounds` with fixed 340×400 — drag-loop rect drift), pushes `kanna:shakeLock`, and `kanna:shakeAsk` runs the model with the renderer's chat tail + hidden scene prompt (`noTriggers:true`); `kanna:unfreeze` releases the position (90 s ceiling); `[shake]` log (weighted count + swings). Agent loop in `chat:send` (Phase 2 chain): when the reply carries a tool call and `agent.enabled`, main runs a chain loop — emits `chat:tool` {name, chain, maxChain}, `await toolbox.execute`, feeds an unquotable internal note (phrased `Real data from your X check…`; tells her when chaining is still possible), re-runs the model (`noTriggers:true`) until a reply has no tool key or `agent.maxChain` (1–5, default 2) is reached. Run #1 is a pure bridge (its text is dropped); each note-fed pass WEAVES the previous result into visible text and may carry the next tool call in the same reply. The VOICE LEADS THE CHAIN (`agent.silentTool`, default on): every woven pass is dispatched whole via `chat:passDone` {index, text, silent} and main awaits `kanna:chainResume` — the renderer shows and speaks the pass, then unblocks main when the utterance ends (builtin `onend`; cloud `durationMs` timer; silent/vanished passes resume instantly; ~5 min safety ceiling per wait). The pass's tool runs only after its speech finishes; a pass may set `"silent": true` to skip its voice mid-chain (final reply never silent; silence changes the voice only — the `"text"` must remain the full woven reply). A dots-only pass (`"..."`) counts as empty and is skipped instantly instead of shown. Each woven pass becomes its own chat turn: resolve carries `passes` + `notes` (`*Waiting while Kanna uses her X tool…*`, same bracketed asterisk pattern as shake history notes), and the renderer pushes one assistant entry per pass with the wait notes as user-side entries in the gaps; passes are dispatched (and spoken) one by one mid-turn, the previous reply sliding into the small prior-turn slot as each new pass starts. Placeholder recovery: no tool key but a fabricated bracket placeholder (`[Time from tool result]`-style) or a note leak → whole pass dropped + `leak` flag, then (agent mode) a recovery pass runs the tool named in the leak bracket (default `time`) and feeds the result as an internal note. Scrubs remove leak lines plus bracket placeholders from every visible text; memory extraction reads the visible replies.
  - `src/main/welcome.js` — welcome-back greeter: five absence tiers (≥5 min bored → ≥30 min happy → ≥90 min teasing → ≥4 h sad → ≥12 h shy) with 6 canned lines each, no-repeat per tier, `{name}` splices remembered user name, no model call.
  - `src/main/settings.js` — settings store at `%APPDATA%\Kanna\settings.json`; API/TTS keys encrypted at rest with safeStorage (DPAPI), plaintext in memory, migration on load. Includes `agent.enabled` (agent/toolbox mode off), `agent.maxChain` (1–5, default 2 — cap on chained tool calls per turn), and `agent.silentTool` (default on — model may "silent" an intermediate chain pass to skip its voice; also `tts.piperUseGpu`).
  - `src/main/memory.js` — durable facts in `%APPDATA%\Kanna\memory.json`; post-turn extraction (frequent mode: any exchange with ≥10-char user text and ≥10-char reply goes through the extractor — short messages teach too); short turns while an extraction is in flight wait in a 3-deep queue (oldest dropped on overflow); injected into system prompt.
  - `src/main/toolbox.js` — real desktop tools the model can call (toolbox plan, Phase 2; design doc: `%USERPROFILE%\.opencode\plan\toolbox.md`). Strict allowlist registry: currently `time` (today's date/time/day of week; no args) and `weather` (local weather via wttr.in — city/temperature/sky/wind/humidity, ~9 s abort window; no args, no key). `describeForPrompt()` gives the model the one-line tool list, `execute(name, args)` is async, validates (unknown names and >512-char args are rejected) and returns a TOOL RESULT string — never shown to the user directly. Gate: only active when Settings → Personality → Agent mode (`agent.enabled`, default off) is on. Later phases add plugins and the sensitive tier (plan file has the full design).
  - `src/main/ai.js` — providers (OpenAI, custom, OpenCode, Anthropic, Gemini), SSE streaming, model listing, JSON reply protocol reader (optional model-driven `intensity` 0–1, an optional `"tool": {name, args}` call, and an optional `"silent": true` voice-skip flag read at stream end — the tool object is extracted with a balanced-brace scan, malformed/truncated tools are treated as absent). Standing `Emotional direction` block + `affect.moodCarry()` continuity line go into every chat system prompt; the `Toolbox` direction block (one tool call per reply, note-fed chaining across replies, no-leak rules, small-model-friendly step templates) is included only when `agent.enabled` is on. `bufferToolText` (agent chat first pass): its text is held and dropped when the pass carried a tool call (pure bridge), or whole-dropped with a `leak` flag on a fabricated bracket placeholder. Continuation chain and recovery passes run unbuffered — they stream live, so Kanna answers the moment each tool note lands, never waiting for the whole chain (a late pass leak can only be scrubbed from history, not the bubble, so capable models chain best). Spam triggers run only for real chat: `userRepeatCount` (hard normalization strips punctuation/emoji/case and collapses letter-runs like `hiiii`→`hi`, plus Levenshtein ratio ≥ 0.7 for near-variants) or `rapidUserStreak` (≥ 3 unanswered user messages in a row = flooding; different content still counts).
  - `src/main/affect.js` — internal affect engine (Phase 1 of the mood system plan → Phase 2 triggers + Phase 3 protocol + Phase 5 affinity): per-family valence/arousal/socialEnergy targets, per-turn blend with jump caps, time decay toward the affinity-biased neutral baseline (Phase 5: `(affinity-30)/70*0.10` valence lift), alias mapping for loose mood words, stop/interrupt nudges, and one-line `[affect]` logs for transitions and turn ends. Long-term `affinity` 0–100 persisted in `%APPDATA%\Kanna\affect.json` (debounced saves, hard flush on quit/reset; load failures keep the default 30). Scoring: affectionate/praise/apology turns +1 (tease +0.5 when not fed up, −1 when fed up; unkind −2; every spam/shaken grudge bump −1). Triggers: shared irritation pool for `noteRepeat` (same-content spam incl. variants), `noteFlood` (unanswered message pile), `noteShake` (shake bursts bump the same pool; grudge persists across turns), levels 1–3 with per-kind style notes; keyword tone read (`noteUserTone` — unkind/affectionate/apology/tease/praise incl. hearts and `:3`) with gates: tease cannot soften her while `annoyed>=2` or family angry, apologies fade the grudge one level per apology turn with guarded mood notes, affection builds a `warm` reservoir (0–3, decays per turn) and doesn't melt until warm≥3; model-reported optional `intensity` (from meta) can override the computed snapshot intensity. All emotion cools one level per quiet turn; triggers are skipped for memory-extraction runs (`plain:true`). Standing-by for the model: `styleNote()` (irritation + tone notes) and `moodCarry()` (one-line continuity of family/irritation). In-memory except affinity; renderer emotes unchanged.
  - `src/main/stt.js` — local Vosk STT server client (PCM streaming, partial/final results; prefers the frozen `kanna-stt-server.exe`, falls back to `py` + `resources/stt/stt_server.py`).
  - `src/main/log.js` — rotating file logger (`%APPDATA%\Kanna\logs\kanna.log`).
  - `src/main/tts.js` — built-in speechSynthesis or cloud (ElevenLabs, OpenAI, Azure, Google); Piper runs CLI or persistent HTTP server (`resources/piper/piper_server.py` / `kanna-piper-server.exe`). Supports `--gpu`; CUDA DLLs are staged automatically.
  - `src/preload/preload.js` — `window.kanna` bridge.
  - `src/renderer/` — `index.html`, `style.css`, `renderer.js`, `settings.js`.
- Renderer uses all 20 emote files (10 pairs: angry, bored, dizzy, happy, neutral, sad, shy, strained, surprise, teasing) + the `assets/still/sleep.png` dozing still and `assets/background/1.png`.
- History is in-memory only; each request sends last 24 messages plus persona.

## Product behavior

- Fixed 340x400 frameless transparent window; no resize/maximize.
- Close hides to tray; Quit only from tray menu; Ctrl+Shift+K summons.
- Window position restored only when it fits a connected display.
- Agent mode (Settings → Personality, default off): lets the model call real desktop tools from the toolbox (`toolbox.js`) via an optional `"tool"` key in the reply JSON, chained up to `agent.maxChain` per turn — each woven reply is its own turn with `*Waiting while Kanna…*` history notes in the gaps. Voice-led: she speaks each pass before its tool runs; `Silent chaining` (Settings → Personality, `agent.silentTool`, on by default) lets the model mark an intermediate reply `"silent": true` so the chain continues without waiting for that pass's voice. With agent mode off, the model never sees tools and answers text-only as always.
- Turn-box: current reply large, previous half small, tap to compose/interrupt, Escape closes, History drawer.
- Memory: durable facts, never secrets; view/clear in Settings -> Memory.
- Mood/speed/hold controlled by model via JSON reply protocol; graceful fallback to raw text. Optional `intensity` 0–1 key (Phase 3 of the mood-system plan) scales the face — face-size bands `i-low`/`i-mid`/`i-high` in renderer; when the model omits it (or streams plain text), the affect engine's computed snapshot intensity stands in (valence/arousal-based), renderer stays in the mid band.
- TTS: built-in or cloud/engine voices, free-text voice ID, rate/pitch sliders, mute toggle, speech-paced typing.
- Provider keys/models remembered separately.

## IPC contract

`settings:get`, `settings:save`, `models:list`, `chat:send`, `chat:stop`, `kanna:back`, `kanna:shakeAsk` (handle), `kanna:unfreeze` (on), `memory:get`, `memory:remove`, `memory:clear`, `affect:get`, `affect:reset` (handle), `affect:resetAffinity` (handle), `tts:speak`, `tts:cancel`, `win:min`, `win:close`. Push events: `chat:chunk`, `chat:meta`, `chat:tool` (agent mode: `{name, chain, maxChain}` before each tool executes), `chat:passDone` (agent mode: `{index, text, silent}` — each woven pass dispatched whole once its stream ends; chain pass `chat:chunk`s stay suppressed), `kanna:shakeLock` (window frozen after a shake burst), `kanna:freezeOff` (unfrozen — reason: `voice done` | `timeout` | `hidden`), `kanna:shake` (unused static-line legacy). Renderer → main file: `kanna:chainResume` (`kanna:chainResume` IPC: the renderer finished speaking one chain pass, or skipped it silently — releases the pass-wait).

`chat:send` emits `chat:chunk` and `chat:meta` {mood,speed,hold,intensity?}, resolves `{ stopped, text, passes, notes }` — `passes` = each woven reply's own turn text (single-entry list for plain replies), `notes` = the `*Waiting while Kanna uses her X tool…*` lines to store between them (may exceed passes when a stop cut a reply short). `chat:tool` fires before each tool executes, `chat:passDone` dispatches each woven pass whole (the renderer speaks it and resumes the chain). Streaming errors reject. `runChat(messages, emit, system, opts)` supports `registerInActive`, `plain` (no protocol reader), `bufferToolText` (`true` = first pass holds its text till stream end, then drops it on a tool call — pure bridge), `noTriggers` (skip affect trigger block — synthetic scene prompts like `kanna:shakeAsk`); the result carries `tool` when the model's reply JSON contained a tool call and `leak` when visible text was a fabricated placeholder.

## Assets

- Emotions are pairs: `<emotion>.png` and intensity speaking variants. Speaking files: most moods ship three intensity variants `<emotion>-speak-i1/-i2/-i3.png` (matching the `intensity` bands — Phase 4 asset work); `neutral` and `dizzy` ship a single shared `<emotion>-speak-all.png`. The `bored` mood's files are named `boring*` (protocol label unchanged, renderer maps at the file layer).
- Current emotions: angry, bored, dizzy, happy, neutral, sad, shy, strained, surprise, teasing. Plus a `still/` folder for art outside the mood cycle (`sleep.png` — shown after ~3 min idle, wakes on any interaction).
- Backgrounds numbered in `assets/background/`.
- `assets/pet-model/` — reserved sprite art for Kanna living outside the stage window (future overlay pet): `animated/lay.webp`, `animated/walk.webp`, `static/sleep.png`. Not wired to any renderer yet; folder kept for the (later, deliberately-deferred) separate pet window described in TODO.md.

- `assets/icon.ico` tray/window; `assets/icon.png` 512x512 installer icon.

## Notes

- npm may gate install scripts; if Electron binary missing run `node node_modules/electron/install.js`.
- Trust `package.json` over this file.
- Main process owns network requests; abortable with AbortController.
- Treat settings.json like `.env`: encrypted key blobs plus plaintext config.
- `memory.js` and `ai.js` lazy-require each other to avoid circular requires.
- No test framework; run `node --check` on touched JS and smoke-test with `npm start`.
